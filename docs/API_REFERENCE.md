# API Reference

Base URL (local): `http://localhost:8000`. Interactive OpenAPI docs are auto-generated by
FastAPI at `/docs` and `/openapi.json` when the backend is running -- treat this file as a
human-readable index, and `/docs` as the authoritative, always-current contract.

All endpoints except `/api/health` and `/api/auth/*` require `Authorization: Bearer <token>`.
Tokens come from `/api/auth/login` (local demo JWT) or a Supabase access token when
`SUPABASE_JWT_SECRET` is configured.

## Auth
| Method | Path | Role | Notes |
|---|---|---|---|
| POST | `/api/auth/register` | any | Creates a user + merchant/supplier profile |
| POST | `/api/auth/login` | any | Returns `{access_token, role, user_id}` |
| GET | `/api/auth/me` | any | Current user |

## Catalog
| Method | Path | Role | Notes |
|---|---|---|---|
| GET | `/api/products` | any | Canonical product list |
| GET | `/api/catalog/offers?product_id=` | merchant | Supplier comparison: price, stock, MOQ, reliability, freshness |
| GET | `/api/catalog/surplus` | any | Open dead-stock listings |

## Supplier self-service
| Method | Path | Notes |
|---|---|---|
| GET/POST | `/api/suppliers/me/inventory` | List / upsert own offers |
| GET | `/api/suppliers/me/allocations` | Incoming order queue (selected-plan allocations only) |
| POST | `/api/suppliers/me/surplus` | List excess stock |
| GET | `/api/suppliers/me/reliability` | Own reliability score + sample size + confidence |

## Orders (merchant)
| Method | Path | Notes |
|---|---|---|
| POST | `/api/orders/parse-text` | Deterministic lexicon parse, returns per-item confidence |
| POST | `/api/orders` | Create order + items |
| POST | `/api/orders/{id}/plan` | Run CP-SAT for cheapest/fastest/most_reliable |
| POST | `/api/orders/{id}/select-plan` | Commit to one plan; starts supplier confirmation |
| GET | `/api/orders` / `/api/orders/{id}` | List / detail (lazily expires overdue confirmations) |

## Allocations (supplier)
| Method | Path | Notes |
|---|---|---|
| POST | `/api/allocations/{id}/confirm` | Full or partial confirm; partial triggers automatic replan |
| POST | `/api/allocations/{id}/reject` | Triggers automatic replan |
| POST | `/api/allocations/{id}/report-shortfall` | Post-confirmation disruption; triggers replan |
| POST | `/api/allocations/{id}/dispatch` | Confirmed/short-supply → dispatched event |
| POST | `/api/allocations/{id}/deliver` | → `fulfilled`; updates order status |

## Payments
| Method | Path | Notes |
|---|---|---|
| POST | `/api/payments/initiate` | Simulated provider by default; Paytm staging if configured and `DEMO_MODE=false` |
| GET | `/api/payments/{id}` | Status |
| POST | `/api/payments/paytm/callback` | Webhook; re-verifies status server-side, never trusts the redirect |

## Reconciliation
| Method | Path | Notes |
|---|---|---|
| POST | `/api/orders/{id}/invoices` | Supplier uploads invoice lines |
| POST | `/api/orders/{id}/receipts` | Merchant records received quantity |
| GET | `/api/orders/{id}/reconciliation` | Ordered vs invoiced vs received, with discrepancy flags |

## Digital Twin
| Method | Path | Notes |
|---|---|---|
| POST | `/api/scenarios/disrupt` | Applies `supplier_outage` / `partial_stock` / `delivery_delay` to a live allocation, reusing the real failover engine |

## Admin
| Method | Path | Notes |
|---|---|---|
| GET | `/api/admin/metrics` | Order counts by status, replan count, supplier reliability average |

## Error shape

All errors are `{"detail": "<message>"}` with a standard HTTP status code (400/401/403/404/409).
Cross-tenant access (e.g. merchant A requesting merchant B's order) returns `404`, not `403`,
to avoid confirming a resource's existence to an unauthorized caller.
